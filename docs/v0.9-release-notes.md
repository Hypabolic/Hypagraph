# Hypagraph v0.9

Hypagraph v0.9 adds code nodes and a sandbox executor. A node can run one
type-checked program in QuickJS without a model turn, then publish declared
facts into the graph.

## Code nodes

- A `code` node holds one TypeScript program, inputs, produces, bounds, and a
  capability allowlist.
- The program is part of the definition and part of the snapshot hash.
- Schema version 7 stores code attempts and results.
- Replay restores a recorded result and never runs the program again.

## Definition-time TypeScript check

- `hypagraph_define` and hypagoal start prepare every code node.
- The host pins the runtime identity. The author cannot supply compiled output
  or a runtime identity.
- Type errors include line and column numbers.

## Deterministic dispatch

- A ready code node runs in the deterministic controller lane.
- The extension does not send ready code work to a model continuation.
- Events use `hypagraph.code.started` and `hypagraph.code.result-recorded`.

## Sandbox and capabilities

- Execution uses QuickJS through a Hypagraph-owned adapter. Hypagraph does not
  depend on `pi-fabric`.
- Bounds are mandatory: timeout, memory, bridge calls, and result size.
- Capabilities deny by default. A revision cannot widen the allowlist.
- M6.2 ships the full control path for `pure` programs. Non-pure host handlers
  land with M6.3.

## Scope verification

- Mutating programs require declared `scope.paths`.
- Verification uses a pre-run baseline and content hashes.
- A further change to a baseline-dirty path is still checked against scope.

## Authoring

- Oversized multi-fact programs produce definition-time advisories.
- Status and skill text describe code nodes and deterministic dispatch.

## Suite

The suite after M6.2 is 117 test files and 729 tests. The focused file is
`tests/m6-2-code-node-sandbox.test.ts` with 39 tests.
