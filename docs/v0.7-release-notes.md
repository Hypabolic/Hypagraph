# Hypagraph v0.7

Hypagraph v0.7 adds the deterministic dispatch lane and the inspectable event
history surface.

## Deterministic dispatch

A canonical action which needs no reasoning runs without a model turn.

- A ready gate evaluates in the deterministic lane.
- A ready check runs through the existing durable check lifecycle in the
  deterministic lane.
- Consumed turns count model turns only.
- The scheduler ordinal counts every selected action in every lane.
- One controller pass may run at most 64 consecutive deterministic dispatches.
- Reload recovers a lost deterministic dispatch so it cannot block later work.

Measured product paths charge fewer model turns for the same canonical result:

| Path | Model turns before M6A | Model turns after M6A |
| --- | --- | --- |
| Bounded lint-repair dogfood | 9 | 4 |
| Loop continuation with an independent region | 10 | 6 |
| v0.6 release product path | 15 | 10 |

See `docs/m6a-dogfood.md`.

## Event history, replay, and explanations

The stored event stream is now a product surface.

```text
/hypagraph history
/hypagraph history 42
/hypagraph history dispatch
/hypagraph history revisions
/hypagraph explain
/hypagraph explain build
```

These commands let the user:

- read a bounded page of the event timeline;
- filter the timeline by lane;
- replay canonical state to any stored sequence;
- compare replay state with live state;
- explain why a node or the goal is not runnable;
- inspect revision segments and discarded results.

`hypagraph_read` exposes the same history and explain views to the model. The
graph pane can enter replay mode without changing canonical state.

See `docs/m6b-dogfood.md` and `docs/dogfood-evidence/m6b-live/`.

## Live Pi dogfood

Two real Pi RPC sessions with `xai-auth/grok-4.5` and the local Hypagraph extension.

### Short path

1. authored one task and one command check from `/hypagoal`;
2. wrote `result.txt` with exact content `m6b-dogfood`;
3. recovered an orphaned model-lane continuation after the task succeeded;
4. dispatched the check in the deterministic lane;
5. completed the goal through canonical workflow state;
6. inspected history, dispatch, revisions, explain, and replay.

### Loop and revision path

1. authored a lint-repair loop, two gates, release note work, and publish work;
2. completed the loop through typed success;
3. blocked `release-note` with `repository-work` and applied one automatic revision;
4. inserted `prepare-note`, completed release note and documentation check, and published;
5. inspected history, dispatch, revisions, loop history, explain, and multi-point replay through 83 events and revision 2.

### Recovery fixes found by live dogfood

- close a durable model-lane continuation when the selected action is no longer runnable and no delivered turn bookkeeping exists;
- cancel an open attempt when a running node is blocked, so automatic revision stays eligible;
- accept `hypagoal_submit_revision` from a durable request-revision continuation when delivery bookkeeping is lost;
- reject `hypagraph_revise` while automatic revision is pending.

## Install

```bash
pi install git:github.com/Hypabolic/Hypagraph
```

Update an existing installation:

```bash
pi update git:github.com/Hypabolic/Hypagraph
```

## Verification

The release suite passes 109 test files and 586 tests.

Schema version remains 6. M6B adds projection and presentation only. It adds no
migration code, no new event type, and no new stored field.

## Deferred

v0.7 remains root-only and sequential in one Pi session. Interaction nodes, code
nodes, external-effect reconciliation, goal families, child Hypagoals, isolated
executors, worktree integration, bounded physical concurrency, dynamic fan-out,
ACP, and named direct agent adapters remain later milestones.
